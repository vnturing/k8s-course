The shape of the cluster

One idea: control plane and workers

A Kubernetes cluster is a control plane plus a set of worker machines called nodes. The nodes host the Pods that make up your application; the control plane manages the nodes and the Pods (Kubernetes: Cluster Architecture).

Each piece has one job. The API server is the front end of the control plane (components). etcd is the store for all cluster data, and the scheduler picks a node for each new Pod (architecture). On every node, the kubelet keeps the Pod’s containers running and kube-proxy implements part of the Service concept (components).

Real clusters vary. In small development clusters, control-plane components and user workloads can share nodes; larger ones separate them (architecture). A single k3s server is itself a complete cluster that can host Pods (k3s quick start). We use separate agents anyway, because the join flow is the part worth practising.

Why k3s, and why on VMs

You mentioned k3s is “best on arm”. It is popular there, but it is not limited to it: the docs list x86_64 first among supported architectures (k3s requirements). Your Intel laptop is fully supported.

The choice here is a teaching one. With one Incus VM per node, each node is a genuine separate machine with its own kernel, hostname and IP. Joining an agent to a server over the network is the same flow you would use with physical servers. That is the experience a single-machine cluster hides.

Retrieval practice

Answer from memory before you scroll back up. Wrong guesses are fine; they are part of the learning.

You run a kubectl command. Which component receives the request first?

  1. kube-scheduler
  2. kubelet
  3. kube-apiserver
  4. etcd

The API server is the front end of the control plane. Other components, and you, talk to it.

Which pair runs on every worker node?

  1. kubelet + kube-proxy
  2. etcd + scheduler
  3. apiserver + etcd
  4. scheduler + kubelet

Node components run on every node. The scheduler and etcd belong to the control plane.

A friend claims k3s only works on ARM boards. Your verdict?

  1. Right: only ARM binaries exist
  2. Right: Intel needs full Kubernetes
  3. Right: x86_64 builds are experimental
  4. Wrong: k3s ships x86_64 builds

x86_64 is a listed, supported architecture in the k3s requirements.
